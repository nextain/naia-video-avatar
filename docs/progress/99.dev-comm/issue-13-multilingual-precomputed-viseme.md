# Issue 13 — 다국어 사전 생성 발화 엔진

GitHub: https://github.com/nextain/naia-video-avatar/issues/13

## 제품 목표

얼굴 이미지는 비공개 Naia 생성 서버에서 Ditto로 한 번만 처리한다. 생성된 발화 동작 영상은 공개 NVA 규격으로 패키징한다. 사용자는 Ditto·CUDA·VRAM이 없는 기기에서 NVA Player에 텍스트와 오디오를 넣어 다국어 미지 문장을 실시간 재생한다.

## 공개와 비공개 경계

- 공개: NVA 규격·검증기·Player·NVA Studio·공급자 비종속 생성 작업 계약.
- 비공개: Naia 서버의 Ditto 실행·모델 자산·생성 품질 분석·운영 자격증명.
- NVA Studio: 생성 결과 영상 추가·교체, 배치, 메타정보 편집, 미리보기, 검증, 패키징.
- NVA Player: 읽기 전용 재생 엔진. GPU 추론 없이 사전 생성 자산을 텍스트·오디오에 맞춰 합성.

## 완료 순서

1. 목표와 성공 기준 고정.
2. 기존 6개 입모양 실험·현재 main·cascade·Ditto·VoxCPM2 갭 분석.
3. 타당성 실험 계획과 구현 계획 작성.
4. 계획 적대 리뷰를 연속 2회 새 차단 발견 없음까지 반복.
5. REQ→UC→TEST-S와 UC→SPEC→TEST-F 추적에 따라 구현.
6. 각 단계 개발 리뷰와 기능 테스트.
7. 공개 Studio/Player↔비공개 Naia 생성 어댑터↔VoxCPM2 cascade 통합 테스트.
8. 테스트 후 적대 리뷰와 전체 회귀.

## 현재 결정

- `sil/a/i/u/e/o`는 비교 기준일 뿐 제품 계약이 아니다.
- 플레이어 코어는 언어별 철자가 아니라 공통 조음 분류를 사용한다.
- 텍스트는 발음 선택을 돕고 오디오는 재생 타이밍의 기준이다.
- 완전한 문장 영상을 미리 저장하지 않는다. 유한한 동작 자산 표현이 미지 문장에 일반화되는지 먼저 증명한다.
- 자연스러움의 최상위 기준은 조합한 최종 영상과 같은 오디오의 전체 문장 Ditto 영상을 전체 프레임으로 비교하는 것이다.
- H1은 인간형 Jina로 먼저 판정한다. 하관 발화층 F/L은 Ditto가 함께 만든 코·볼·턱·목 움직임을 절단하므로 제품 후보에서 제외했다. 현재 표현 후보는 NVA에 등록된 `head_image` 전체이며, 전체 문장 Ditto W는 계속 품질 기준선이다. Jina 원본은 158×243 RGBA이고 런타임 배치는 `[280,70,158,242]`다. `[104,0,512,512]` 몸 크롭으로 수행한 이전 실험은 원본 자산이 아니므로 H1 증거에서 제외했다.
- Jina H1이 통과한 뒤에만 큰 고양이 머리 Naia를 같은 문턱의 별도 H2로 선등록한다. 사람형 성공을 Naia 성공으로 합쳐 보고하지 않는다.

### 확인된 기술 사실

- Ditto 온라인 경로는 이전 키포인트 열과 오버랩을 보존한다. 따라서 고립된 모음 한 프레임은 원본 생성기의 시간 문맥을 보존하지 못한다.
- 보류 브랜치의 6상태 NVA는 실제 WebM 자산과 재생 코드를 남겼지만, 자연 발화 타이밍 대신 고정 간격과 문자열 휴리스틱을 쓴다. 제품 근거로 승격하지 않는다.
- eSpeak NG는 네 대상 언어의 음소열을 만들 수 있지만, 음성의 실제 경계는 별도 강제 정렬 공급자가 맡아야 한다.
- 단일 경량 정렬기로 검토한 BFA는 문서상 중국어·일본어·한국어를 지원하지 않는다. 영어 대조군 이외의 공통 제품 경로로 채택하지 않는다.
- 로컬에는 RTX 3090 2장, 건강한 Ditto TensorRT 서비스, FFmpeg 8, eSpeak NG와 Chromium이 있다. 타당성 실험은 외부 유료 GPU 없이 실행할 수 있다.
- Jina 고정 자산으로 Ditto의 머리 자세·눈·비입 표현을 소스 상태에 두고 입 표현점만 구동한 탐색 렌더가 성공했다. 중립 프레임에서 한 번 만든 하안면 support 밖 알파를 0으로 제한한 투명 발화층은 눈 교집합 0px, support 밖 생성 알파 최대 0을 지켰고, 전체 입 전용 렌더 대비 SSIM 0.996632, PSNR 47.023535dB였다. 이는 표현 분리의 가능성만 보인 EXPLORE 결과이며 조각 전환·다국어 자연스러움 PASS는 아니다.

## 제안 아키텍처

```text
NVA Studio (public) -- GenerationJob --> Naia generation adapter (private)
      ^                                      |
      | GenerationResult + provenance        | VoxCPM2/G2P/alignment -> Ditto
      +---------------------------------------+
      |
      +-- package: body + neutral_head + alpha speech_motion assets + manifest
                              |
text + audio + optional timeline --> NVA Player (public, CPU/browser) --> body/head composition
```

- `speech_motion.inventory`: 언어 이름이 아닌 공통 조음 분류와 침묵 단위.
- `speech_motion.units`: 정적 기준, 방향성 전이 또는 실험에서 선택된 문맥 단위의 자산 인덱스.
- `speech_motion.alignment`: 플레이어 입력 타임라인의 버전·시간 단위·신뢰도 계약.
- `speech_motion.provenance`: 생성 공급자, 모델/소스 해시, 생성 시각, 품질 보고서 해시.
- 고품질 경로는 `text + audio + SpeechPlan`이다. Player는 정렬을 추론하지 않고 검증·소비만 한다. VoxCPM2 cascade나 교체 가능한 서버 정렬 공급자가 오디오 시간선과 공통 조음 단위를 만든다. `text + audio`만 있는 근사 미리보기는 고품질로 표시하지 않는다.
- 작업 요청은 원본/base64/임의 URL 대신 일회성 업로드에서 받은 불투명 `source_asset_id`만 쓴다. 품질 보고서와 생성 자산 해시는 결과 manifest에 결박한다.
- H1의 고정 표본·분석기 교정·13단위/169+64 상한·100 MiB·Chromium CPU 조건은 `docs/research/issue-13-feasibility-protocol.md`가 정본이다.

### 단계와 내부 게이트

1. **타당성 CONFIRM**: Jina NVA에 등록된 같은 `head_image`·몸·오디오로 A 정적 6상태, B 방향성 전이, C 문맥 단위의 전체 머리 조합을 전체 문장 Ditto W와 비교한다. manifest 밖에서 새로 자른 영역은 입력으로 허용하지 않는다. 머리와 목 접합부가 보이는 전체 영상의 자연스러움을 최상위로 판정한다. 기존 F/L 하관 방식은 대조 기록으로만 보존하고 PASS 후보로 사용하지 않는다. 통과 뒤 Naia는 별도 H2로 판정한다.
2. **계약 RED**: 선택 표현의 스키마·생성 작업·타임라인·Player 상태·Studio 왕복 실패 테스트를 먼저 만든다.
3. **공개 GREEN**: v0.2 하위 호환 스키마/검증기, Player 코어/뷰어, Studio 작업 UI를 구현한다.
4. **비공개 GREEN**: 깨끗한 cascade 작업 트리에서 VoxCPM2/G2P/정렬/Ditto 생성 어댑터와 결과 출처를 구현한다. 현재 사용자 수정 파일은 건드리지 않는다.
5. **통합**: Jina NVA → 생성 작업 → 결과 가져오기 → 네 언어 오디오/타임라인 → GPU 없는 Chromium 재생을 H1로 검증한다. 통과 뒤 Naia NVA는 같은 경로의 별도 H2로 검증한다.
6. **수렴 리뷰**: 계획, 개발, 테스트, 통합 각 단계에서 적대 리뷰를 수행하고 연속 2회 새 차단 발견 없음까지 수정한다.
7. **회귀/인계**: 추적성·계약·제품 보존·빌드·브라우저 E2E·전체 회귀 후 이슈에 증거를 남기고 커밋·푸시한다.

- 품질 지표가 실제 자연스러움 대신 자기 생성 Ditto를 복사하는 점수에 머무르지 않는가?
- 쌍 전이의 N² 용량과 디코더 전환 비용을 숨기고 있지 않은가?
- 텍스트 휴리스틱을 오디오 정렬이라고 잘못 부르고 있지 않은가?
- 네 언어 중 하나라도 별도 플레이어 분기를 요구하는가?
- 공개 Studio가 비공개 모델·원본·자격증명을 누출할 수 있는가?
- 기존 v0.2 NVA와 cascade 소비자 경로를 깨뜨리는가?
- GPU가 꺼진 브라우저에서도 같은 통합 결과가 재현되는가?
- 입술 점수는 좋아도 머리 자세·시선·깜빡임·밝기 또는 헤드-어깨 접합부가 컷마다 튀지 않는가?
- 하안면 합성이 얼굴 내부에 새로운 경계를 만들거나 Ditto의 턱·볼·머리 동작을 훼손하지 않는가?
- 차분 알파 발화층이 입 밖의 Ditto 재구성 잡음까지 포함하거나, 반대로 필요한 턱·볼 변화를 잘라 자연스러움을 잃지 않는가?

## 2026-08-01 구현·검증 현황

### 2026-08-02 원본 NVA 머리 한국어 컷 실험

- 실제 VoxCPM2 문장 `안녕하세요. 나이아 비디오 아바타의 실제 조합 발화 품질을 확인합니다.`를 전체 문장 Ditto W와 1.2초 자연 음성 창 13개를 독립 생성한 R로 비교했다.

- 80ms·160ms·240ms를 비교했으며, 원격 컨테이너 파일 해시와 W/R 출력 크기까지 결박한 240ms 최종 재실행의 동일 전환 시점 최대 변화는 W 0.10583, R 0.12817, 추가 변화 +0.02234로 가장 작았다. 발화 영역 SSIM은 0.72637이었다.
- 머리 배치 밖 몸 영역의 디코딩 후 SSIM은 0.99929였다. 합성 단위 테스트는 배치 밖 픽셀의 정확한 보존을 확인했다. Ditto 입력에 어깨가 없으므로 이전 임의 512 크롭에서 보인 어깨 재생성은 발생하지 않는다.
- 앞서 보고한 512 몸 크롭·공간 정렬 결과는 잘못된 입력 자산으로 수행했으므로 기술 결론과 품질 증거에서 제외했다. 감사 이력은 품질 미리보기 문서에 정정 사유와 함께 남긴다.
- 이 결과는 자연 음성 창으로 컷 연속성만 분리한 탐색 실험이다. 재사용 가능한 발음 atlas나 다국어 H1 증거가 아니며 공식 판정은 계속 `INCONCLUSIVE`다. 직접 비교 영상과 지표 정의는 `issue-13-quality-preview.ko.md`에 있다.

### 계획 게이트

- 고정 프로토콜과 V-모델 추적표는 같은 최종 문서 상태에서 독립 리뷰 2회 연속 `CLEAN`을 받았다. 증거는 `.agents/reviews/issue13-planning-convergence-2026-08-01.md`다.

### 공개 GREEN 구현

- `SpeechPlan v1`: 고정 13개 공통 조음 단위, 오디오 SHA-256/정수 마이크로초 시간축, 정렬기 출처, `aligned|approximate`, 선등록된 40ms 미만 이벤트 병합 규칙.
- `speech_motion`: 기존 NVA v0.2와 하위 호환되는 선택 확장. 중립 머리, 무손실 VP9 atlas, atlas index, 생성 영수증의 번들 내부 상대경로만 담는다.
- `GenerationJob/GenerationResult`: 원본 URL/base64/경로와 미등록 필드를 실패 닫힘으로 거부하고 불투명 source/job ID, 자산 해시, 품질 5개 게이트, 원본 삭제 시각을 요구한다.
- Studio: HTTPS 일회성 원본 업로드, 작업 생성·진행률·취소, 결과 ZIP 가져오기, 자산 전체/구간 SHA-256 검증, manifest 결박, `.nva` 재패키징. Ditto 실행·모델·자격증명은 포함하지 않는다.
- Player/Viewer: `.nva + audio + SpeechPlan` 읽기 전용 진입점, 언어 필드 없는 5프레임 전이 스케줄, 정확히 2프레임 raised-cosine 교차 혼합, 첫 두 단위 미리 읽기, 완료·취소·오류 상태 복원, HTTP Range/로컬 `Blob.slice`, 두 `<video>` 교대 디코딩, `몸 → 중립 머리 → 최대 두 투명 발화층` 합성. 생성 영수증과 자산 bytes/SHA-256도 재생 전에 다시 결박한다.
- 비공개 Naia 생성 API: `nextain/naia-omni-cascade#36`의 격리 브랜치에 일회성 원본 업로드, 작업/취소/번들, 품질 실패 닫힘, 100 MiB 최종 ZIP 제한, bearer/CORS, 재시작 상태 복구와 generator 하위 프로세스·고아 그룹 정리를 구현했다. 실제 Ditto/정렬 명령은 고정 subprocess 포트 뒤에 남아 있다.

### 자동 검증 증거

- 전체 Node 회귀: `node --test src/test/*.test.mjs` — 2026-08-01 최종 재실행에서 74/74 통과. Studio 세션 전용 bearer 전달, 원본 ZIP 압축 해제 전 한도 검사, 브라우저 프레임 함수 호출 문맥 회귀를 포함한다.
- Studio Chromium 왕복: HTTPS 가짜 비공개 생성 서버에 원본 업로드 → 작업/조회/삭제/ZIP → 자동 가져오기 → 수동 재가져오기 → 전체 자산 SHA-256/bytes → atlas 두 slice SHA-256 → `.nva` export → manifest와 `speech/*` 6개 자산 재로드가 통과했다. `speech/atlas.bin`은 ZIP STORE였다.

- Viewer Chromium 통합: 실제 Jina `speak_body.webm`과 당시 테스트용 512 PNG, VP9 알파 조각 atlas, 600ms WAV와 공통 13단위 SpeechPlan을 `.nva`로 묶어 `viewer.html`에서 검증·디코딩·재생했다. canvas 720×1280, 오디오 450ms 이상 진행, 콘솔/page 오류 0이었다. 이 테스트는 플레이어 배선만 검증한다. 테스트용 512 PNG는 원본 Jina `head_image` 품질 증거가 아니다.

### 정직한 현재 판정

`INCONCLUSIVE`다. 공개 계약·Studio 왕복·GPU 없는 브라우저 알파/Range 기반은 구현 가능성이 확인됐지만, 아래 H1 차단 항목이 남아 있다.

1. 비공개 생성 API 뒤의 전체 13단위 B-F/C-F 생성 명령과 VoxCPM2→MFA SpeechPlan 어댑터. 실제 Ditto 6전이 검사기는 연결됐지만 전체 atlas 생성기는 아직 아니다.
2. Jina B-F/C-F atlas 실제 생성과 네 언어 FLEURS 80문장 조합 영상.
3. 고정 SyncNet/MediaPipe/LPIPS 자동 게이트와 12명 눈가림 720쌍 평가.
4. Chrome 고정 환경의 cold/warm 첫 프레임 p95, RTF p95, 100MiB 최종 묶음 측정.

따라서 “자연스럽다”, “다국어 H1 PASS”, “Naia 고양이에도 된다”는 아직 선언하지 않는다. Jina H1을 통과하기 전 Naia H2로 확장하지 않는다.

# Test Receipts and Quality Control

English | [한국어](./README.ko.md)

This directory archives verification receipts for integration tests (IT), end-to-end user journey tests (E2E), and independent quality control (QC) records in accordance with the [naia-pj-adk](https://github.com/nextain/naia-pj-adk) standard pipeline.

---

## 1. File Naming Conventions

All verification records in this directory follow strict naming conventions:

- **Integration Test Receipts (IT)**:  
  `RECEIPT-IT-{ISSUE}-{YYYYMMDD}-{SEQ}.md`  
  (e.g., `RECEIPT-IT-22-20261008-01.md`)
- **End-to-End Test Receipts (E2E)**:  
  `RECEIPT-E2E-{ISSUE}-{YYYYMMDD}-{SEQ}.md`  
  (e.g., `RECEIPT-E2E-22-20261008-01.md`)
- **Independent Quality Control Records (QC)**:  
  `QC-{NN}.md`  
  (e.g., `QC-01.md`)  
  *Note: QC records are conducted exclusively by an independent session reading only PC and SP, and are not generated by the implementation agent.*

---

## 2. Receipt Field Specification

Every test receipt strictly declares the following fields derived from the canonical [TEST-RECEIPT.ko.md](https://github.com/nextain/naia-pj-adk/blob/main/docs/pipeline/TEST-RECEIPT.ko.md):

### 2.1 Metadata
- **Receipt ID**: Unique identifier conforming to the naming convention.
- **Test Type**: `IT` (Integration test without UI) or `E2E` (End-to-end user journey test).
- **E2E N/A**: `N/A` (only if SP defines no screen) or `REQUIRED` (default).
- **SP Section Reference**: *[Required when E2E is N/A]* Specific section in SP confirming no UI exists.
- **Issue**: Associated GitHub issue identifier (`owner/repo#number`).
- **Manifest Unit / REQ-IDs**: Linked requirement or feature unit (`FE-NN`, `REQ-NNN`).
- **Target Repository**: Repository name (`nextain/naia-video-avatar`).
- **Target Commit**: Git commit SHA evaluated (`git rev-parse HEAD`).
- **Executed At**: Timestamp in ISO 8601 format.

### 2.2 Arithmetic Results
Explicit numerical table preventing false completion claims:
- **Total Tests**: Number of tests executed.
- **Passed**: Count of passing tests.
- **Failed**: Count of failing tests (`Failed > 0` prohibits PASS).
- **Skipped**: Count of skipped tests (must explain reason).
- **Exit Code**: Process exit code (`0` for success).
- **Final Verdict**: `PASS` or `FAIL` / `BLOCKED`.

### 2.3 Environment and Artifacts
- **Tested Address**: Network address or `"None (module test)"`.
- **Artifact File Path**: Relative path to generated test outputs or `"N/A"`.
- **Preceding IT Receipt**: *[Required for E2E]* Path and commit SHA of passing IT receipt.

### 2.4 Independent Reviewer Questions
1. **Q1**: Did the tested address resolve to the actual component route?
2. **Q2**: Do artifact files exist on disk and were they directly inspected?
3. **Q3**: Does E2E reference a valid preceding IT receipt? (Or is SP section valid for N/A?)

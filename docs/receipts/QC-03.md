### Blocking
None. All functional capabilities, security invariants, error boundaries, state transitions, layout constraints, and lifecycle revocations defined in `PC.md` and `SP.md` execute as specified.

### Non-blocking
1. **Pluralization in Status Text**: In the ready status line (`"Ready · <Name> · N speech videos · N actions"`), when the action count is 1 (as seen in `sample 2`, `sample 3`, `sample 4`, and `sample 6`), the string outputs `"1 actions"` rather than singular `"1 action"`.
2. **Background Color CSS Transition**: The stage element defines a CSS transition `transition: background-color 0.2s;`. When selecting colors via `input#backgroundColor`, the DOM inline style is updated immediately while the visual computed color interpolates smoothly over 200ms.
3. **Sample Fetch Error Granularity**: When the sample catalog catalog endpoint fails, the UI surfaces `"Sample catalog blocked: <reason>. You can still open a local file."`. When an individual sample asset bundle fetch encounters a network or HTTP error, it displays `"Blocked: request failed with HTTP <status>"` under the generic bundle block format.
